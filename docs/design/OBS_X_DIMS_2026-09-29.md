# New observation dims on top of r8c ("obs-X", 2026-09-29)

Owner goal (2026-09-29): brainstorm new observation dims, test them and mixtures
of them on top of r8c, modify existing dims only with a reasoned hypothesis,
record everything, then start training r8c with the best mixture.

Status: **done 2026-09-29.** Winner: **`line` + `run`** (betting-line summaries +
all-in equity with runouts) — about +0.02 bb/seat-hand over r8c at the same
update, positive on every deal set in both modes. **Production `vSix7`** =
r8c's recipe + `--obs-x-groups line,run`, continuing that test run (x2c, u1493),
15M rows per update, started 2026-09-29 on the pod's local disk. See
"Final standings" and "Decision" below.

## What the model already sees (1171 dims)

Cards (hero hole, both boards as multi-hots), street, per-seat active / all-in /
stacks, pot scalars, a 32-action history window (seat, fold/check/call/raise,
street, chips, pot fraction per slot), SPR, pot odds, made-hand categories, draw
flags, pair / board structure, straight and flush nut distances and outs,
seat-exists, commits, last aggressor, button distance, double-board overlap
(shared ranks, flush / straight made-draw on both boards), opp-outcome fractions
vs random 2/3/4-card holdings, per-board ahead/tie/behind, blockers, effective
price, log SPR, and the v7 stack / board / double-board blocks (1020-1170).

Two gaps stand out:

1. **Equity never looks at future cards.** Every equity-like input compares the
   hands as they stand on the current board ("current-rank dominance", no runout
   sampling — `outcome_features_mc`). On the flop a big wrap + flush draw that is
   a favourite looks weak; the network has to reconstruct draw equity from outs
   counts.
2. **The action history is raw.** 32 slots of one-hots; "did seat 3 raise this
   street?" needs the first layer to combine a seat one-hot with a gate one-hot
   in the same slot, for every slot — nothing summarizes the line per player.

## Implementation (side worktree `C:\Users\themi\plodbnet-exp` + pod `/root/plx`)

- A new optional **75-dim tail after the 1171** ("obs-X"), switched per run by
  `--obs-x-groups run,range,line,pos` (a bit mask; groups that are off stay
  zero, so every run shares one width). Rust only (the fast training encoder):
  `GameState::x_runout_equity` / `x_range_stats` (engine.rs), `encode_x_tail`,
  `set_obs_x_groups`, a per-(env, seat) cache keyed like the opp-outcome memo,
  `full_dim()` (bindings.rs). Python: `encoding.OBS_X_*`, env / rollout /
  compact-storage / trainer plumbing, `scripts/pad_obs_x.py` (zero-pads a
  1171-dim checkpoint, its optimizer sidecar and its pool siblings),
  `scripts/h2h_x.py` (matchups where each model reads only its own groups).
- Layout of the tail: `run` 0-6 = [eq1 A, eq1 B, scoop1, scooped1, eq2 A, eq2 B,
  scoop2] (48 Monte-Carlo runouts, deterministic seed from the cards); `range`
  7-16 = [top50/20/5 A, top50/20/5 B, nut density A/B, hero nuts A/B] (exact, from
  the per-street pair table); `line` 17-62 = per seat [raises this hand /3,
  raised this street, raised last street, called this street, checked this
  street] then 6 street-level counts; `pos` 63-74 = acts-after mask (8), count,
  must-answer-a-raise count, closes action, first to act.
- Default path unchanged: the exactness check (2 tiny CPU updates, every tensor
  of the checkpoints and optimizer sidecar hashed) is BIT-EXACT vs HEAD 80048a0.

## Verification

- base 1171 dims identical with the tail on / off;
- `line` and `pos` equal an independent numpy re-implementation on every live
  row (hundreds of random states, 2 / 3 / 6 seats, all streets);
- `range`: top-5% ≤ top-20% ≤ top-50% share, nuts ⇒ share ≥ ½, densities in (0, 1];
- `run` vs an independent numpy Monte Carlo on the engine's 5-card-hole strength
  function (6,000 vs 3,000 samples): mean |diff| 0.006, no bias;
- a zero-padded r8c plays exactly like r8c (top choice vs top choice: 0.0000);
- `h2h_x.py` reproduces `h2h_cross.py` exactly for plain 1171-dim models.

## Test design

Round X1: every run continues r8c from its final state (u1461: weights, Adam,
magnet reference, opponent pool, random stream) on the r8c recipe at 5M rows per
update for 32 updates; candidates start from the zero-padded twin (identical
play) with ONE group on; the control continues at 1171 inputs. Each candidate is
scored head-to-head against the control at the same update (8 / 16 / 24 / 32),
sampled and top choice, 61,440 paired hands per match. Round X2: mixtures of the
groups that helped (+ M1).

**Lesson — the evaluation's real noise is the table-setup sample, not the hands:**
each matchup draws only 30 (seats, stacks) configs, a model can be better at
some setups and worse at others, and the per-hand se (±0.012-0.017) hides a
between-config spread that moves results by 0.02-0.05 between seeds. `h2h_x.py`
now also prints the between-config se; the finalists are re-scored with 150
configs x 512 deals (seed 13). Averaging checkpoints does NOT remove this noise
when every checkpoint is scored on the same seed (they share the same 30
setups) — only other seeds / more setups do. So effects below ~0.03 measured on
one seed — including the small ones of rounds 3-8, which all used seed 7 — are
within noise unless confirmed on other seeds; the large ones (all-actions
+0.13, r8c's climb, confirmed head-to-head on seeds 8 and 9) stand.

**Round X1 on seed 7 alone** suggested `line` best and `run` flat — the fresh
seeds below overturned both (see "Final standings").

## Decision

- **`line` + `run`**: tied best overall (+0.023) with all four groups, the only
  mixture positive on all six numbers (3 seeds x 2 modes), better in normal play
  than all four, and ~20% cheaper (no `range`). `run` is the ingredient that
  carries the gain (alone: top choice +0.025 on 4 seeds); `line` alone is
  slightly negative but helps `run` in normal play (+0.021 vs +0.011).
- The price: the `run` Monte Carlo makes an update ~60% slower, i.e. ~40% fewer
  updates per day. At r8c's late climb (~+0.03 per 20 updates) that costs about
  as much per day as the +0.02 one-off gain buys — the cheaper `line,range,pos`
  (+0.015, ~+20% time) is the alternative if updates per day matter more. The
  shared-width design lets production switch groups later without conversion
  (a group's weights just start at zero).
- **M1** (training on the site's 1024-sample opp-outcome features): no
  measurable gain (+0.007 mean, within noise) at +15-20% encode cost — dropped.
- Not tested, strongest next idea: **E1**, a critic-only input of every seat's
  TRUE runout equity given all hands (the critic uses even the random-hand
  `run` features heavily: its column norm reached a third of a typical input's).

## Method lessons

1. Zero-init new input columns on a padded checkpoint make an exact A/B: the
   padded model plays identically at the start (verified 0.0000 top-choice edge).
2. One evaluation seed hides the biggest noise source: the 30 table setups a
   matchup samples. Seed 7 alone ranked `line` first and `run` flat; seeds 11 /
   13 / 17 reversed that. Use 150 configs (`--configs-per-tier 50 --deals 512`)
   and 2-3 seeds for effects of a few hundredths of a bb.
3. The first-layer column norms (`x_weight_use.py`) show which new inputs a run
   is learning to use long before a matchup can resolve it.
4. In bash, `GROUPS` is a read-only built-in: a launcher variable of that name is
   silently replaced by the user's group id (the first vSix7 launch failed on it).
